# camt053-loader-mt942 v0.0.20

No parser changes: `parse_mt942` behaves exactly as it did in 0.0.16.
What this release adds is the tooling this repository was missing, and a
version number that agrees with the rest of the suite.

## Why the number jumped from 0.0.16

The `camt053` suite ships **one version number across all six packages**
by policy, and it had drifted to six different ones — 0.0.18, 0.0.18,
0.0.19, 0.0.18, 0.0.16 and 0.0.16. Nothing breaks when that happens,
which is exactly the problem: a member left a release behind still
installs, still imports, and still passes its own tests. Only the index
disagrees, and only if somebody looks.

All six now sit on **0.0.20**.

## A benchmark

`benches/bench_parse_mt942.py` measures parse throughput along the two
axes that actually move in production.

MT942 is *polled*, not delivered. A treasury system asks for movements
since the last poll, and how many that is depends on how busy the account
was — not on anything the caller chooses. A quiet hour returns a handful
of `:61:` entries; the hour a payroll run lands returns thousands. The
second axis is reports per file, because a system polling many accounts
hands over one file containing many reports.

| entries | ms | ns/entry |
| ---: | ---: | ---: |
| 10 | 0.08 | 8,204 |
| 100 | 0.53 | 5,319 |
| 1,000 | 7.17 | 7,169 |
| 5,000 | 41.09 | 8,217 |

**Growth exponent 1.00 — linear.** The many-reports axis measures 1.09.

That exponent is the point. A parser that has gone superlinear — because
some lookup rescans the entries already parsed — looks perfectly healthy
on a ten-entry fixture and falls over on the busy hour. No unit test
catches it.

The benchmark's own docstring says to read the exponent rather than
`ns/entry` at the smallest size: ten entries parse in well under a
millisecond, close enough to timer noise that the per-entry figure swings
by a factor of two between runs while meaning nothing.

## A scheduled drift check

`scripts/check_suite_consistency.py` runs daily and compares this tree,
and every published member, against PyPI. It exits non-zero when they
disagree, so the schedule becomes a notification rather than a report
nobody opens.
