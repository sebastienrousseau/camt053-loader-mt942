# camt053-loader-mt942 v0.0.23

The camt053 suite's 0.0.23 release, in lockstep with `camt053` 0.0.23.
Two parser fixes, and the checks this repository was missing.

## `:61:` supplementary details

A `:61:` statement line can run onto a second line, subfield 9
(*Supplementary Details*). The parser joined the two before matching, so
the second line ended up glued to the servicer reference:

```text
:61:2606210621C500,00NMSCREF1//CREF1
/OCMT/EUR500,00/
```

gave `account_servicer_ref = "CREF1/OCMT/EUR500,00/"`. It is now `CREF1`.
The supplementary details are kept, as the entry's first
`TransactionDetails`, ahead of any `:86:` text: the model has no
entry-level field for them. If you read `entry.details[0]` expecting the
`:86:` text, check entries that carry a second `:61:` line.

## CRLF

`parse_mt942` said CRLF and LF were both fine. They were, except that a
multi-line value kept its `\r`. A CRLF report now parses to exactly the
document its LF twin does.

## Checks

- A complexity gate with a baseline that can only shrink. `parse_mt942`
  was the one function over the ceilings; it now dispatches through a
  handler table, and 40,000 generated reports parse identically before
  and after.
- `scripts/verify_versions.py` checks every place the version is
  written. The README on PyPI had said "Latest release: v0.0.14" for two
  releases.
- The suite-consistency job compares this tree with this package's own
  release.
- Fuzzing, coverage-guided (Atheris) on every change and property-based
  (Hypothesis) in the test suite: any input either parses or raises
  `ValueError`.
- OpenSSF Scorecard, DCO and `pip-audit` jobs, SHA-pinned actions,
  hash-pinned toolchains, REUSE-compliant licensing, SLSA provenance on
  the published files.

## Upgrading

`pip install --upgrade camt053-loader-mt942 camt053`. The `camt053`
floor is now 0.0.20.
